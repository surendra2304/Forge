# PHASE 0 — TOTAL COMPREHENSION

## (a) What this project IS, and its inferred dream state

**FORGE** is an **Autonomous Software Engineering Engine**. You give it a high-level natural-language
goal (`forge build "Create a robust CLI Todo utility with JSON persistence"`), and it:

1. provisions an isolated sandbox at `workspaces/task_<id>/`,
2. decomposes the goal into a canonical **8-stage hierarchical tree → executable DAG**
   (`app/planning/planner.py` + `app/planning/graph.py`),
3. dispatches each DAG wave to a **specialist agent persona** (planner / architect / developer /
   frontend / backend / tester / debugger / security_reviewer / release_engineer) in parallel via
   `asyncio.gather`,
4. writes code through a **permissioned, sandbox-confined tool layer** (`app/execution/`),
5. runs an **objective verification battery** (`app/verification/`) — AST build parse, Ruff lint,
   pytest, runtime smoke, secret scan, feature-presence, performance, quality, accessibility,
6. self-repairs failures with an **anti-loop controller** (`app/recovery/`),
7. packages a delivery manifest + git release tag (`app/execution/delivery.py`),
8. persists everything (tasks, graphs, checkpoints, audit trail) to **SQLite WAL** (`app/memory/`),
   exposed over **FastAPI REST + WebSocket + a read-only web dashboard**.

**Inferred dream state** (the template placeholders were left blank, so this is derived from
`README.md`, `docs/`, `SYSTEM_MANIFEST.md`, `FORGE_DIARY.md`):

> *"A 100% standalone, evidence-first autonomous software engineer: point it at a goal, walk away,
> and come back to verified, packaged, deliverable software — with an honest audit trail proving
> every claim. It is the local SWE node of the 9-agent FRIDAY Universe, speaking authenticated
> REST/WebSocket to its peers, and it continuously improves itself from its own failure telemetry."*

Three pillars are load-bearing in that vision: **(1) objective evidence over model confidence**,
**(2) strict sandbox isolation**, **(3) honest reporting** (never claim success that verification
didn't earn). Everything below is judged against those three.

# PHASE 2 — BUG HUNT (prioritised)

## CRITICAL

### CRITICAL-1 — `TerminalTool` timeout handler kills its own parent process group
- **File/line:** `app/execution/terminal.py:168` (`asyncio.create_subprocess_shell`) and `:196-204`
  (timeout branch, `os.killpg(os.getpgid(process.pid), signal.SIGKILL)`).
- **Root cause:** the subprocess is spawned without `start_new_session=True`, so it inherits the
  caller's process group. `os.getpgid(child_pid)` therefore returns *the parent's* pgid, and
  `os.killpg(...)` signals the whole group — the Python process running FORGE included. On Windows
  the `taskkill /F /T /PID <child>` path is safe, which is exactly why the suite only ever passed on
  the Windows runner.
- **Evidence:**
  - `python -m pytest tests/test_prompt4_forge.py -q` → `Killed`, exit 137.
  - `setsid python /tmp/prove_bug.py` → `PROBE_EXIT=137`, "SURVIVED" never printed.
  - `pytest` under `start_new_session=True` → `returncode: -9` (= SIGKILL).
  - Minimal repro `pgtest.py`: `child pgid == parent pgid → True`.
- **Impact:** (a) the full test suite cannot run as a unit on Linux — the exact failure CI
  mis-diagnosed as OOM; (b) in production, **any timed-out command in a task sandbox kills the
  uvicorn worker**, taking down the whole API; (c) any library embedding `TerminalTool` inherits the
  same hazard.
- **Proposed fix:** spawn with `start_new_session=True` on POSIX (and keep `CREATE_NEW_PROCESS_GROUP`
  on NT), then kill the *child's own* group. Also make the timeout branch fall back to
  `process.kill()` and never touch the parent's group. Regression test: a command that sleeps past
  the timeout must return `timed_out=True` **and the test process must still be alive**.

### CRITICAL-2 — Artifact download endpoint has no path containment
- **File/line:** `app/api/tasks.py:406-424` (`artifact_file = paths.artifacts / filename`).
- **Root cause:** `filename` is interpolated straight into a path with no `relative_to()` check —
  unlike `WorkspaceManager.save_artifact` (`app/core/workspace.py:196-208`) which *does* validate.
- **Evidence:** calling the handler directly with `filename="../../../pyproject.toml"` returns a
  `FileResponse` whose `.path` is `/home/user/Forge/workspaces/task_tt/artifacts/../../../pyproject.toml`.
- **Mitigating factor (honest):** over HTTP, Starlette's path-param regex `[^/]+` rejects any value
  containing `/`, so `..%2f..%2fpyproject.toml` currently 404s at the router
  (`{"detail":"Not Found"}`). This is **accidental** protection by the framework, not by the code.
- **Impact:** a latent arbitrary-file-read that becomes live the moment the router pattern changes,
  a proxy normalises the path, or the handler is reused. Also: the endpoint is the only `/tasks`
  handler that never validates the task exists.
- **Proposed fix:** resolve + `relative_to(artifacts_root)` containment check, mirroring
  `save_artifact`; 404 on escape. Regression test for both direct-call and HTTP traversal attempts.

## HIGH

### HIGH-1 — `since_timestamp` / `include_archived` filters are applied *after* the SQL `LIMIT`
- **File/line:** `app/api/tasks.py:127-165`.
- **Root cause:** `store.list_tasks(state=..., limit=...)` pushes `LIMIT` into SQL; the Python-level
  `since_timestamp` and `archived` filters then run on that already-truncated page.
- **Evidence:**
  ```
  list_tasks(limit=3)                       -> ['task4','task3','task2']
  since filter applied AFTER limit          -> ['task4','task3','task2']   (expected ['task0','task1'])
  ```
- **Impact:** `GET /api/tasks?since_timestamp=...` silently returns the wrong set — and can return
  an *empty* list for a time window that has data. Any FRIDAY-side "what changed since X" poll is
  broken.
- **Proposed fix:** filter in SQL (`WHERE updated_at >= ?`), or over-fetch then filter then slice.
  Regression test with a time window that only older tasks satisfy.

### HIGH-2 — Two `/tasks` implementations disagree on "latest checkpoint"
- **File/line:** `app/api/tasks.py:214` uses `checkpoints[0]`; `app/api/routes.py:196` uses
  `checkpoints[-1]`. `StateStore.list_checkpoints` orders `step_number ASC`.
- **Evidence:**
  ```
  checkpoints order: [1, 2, 3]
  api/tasks.py   latest_checkpoint_id -> step 1   (OLDEST)
  api/routes.py  latest_checkpoint_id -> step 3   (NEWEST)
  ```
- **Impact:** `GET /api/tasks/{id}` reports the *first-ever* checkpoint as `latest_checkpoint_id`.
  Any resume-from-checkpoint consumer is pointed at stale state. `/api/v1/tasks/{id}` is correct.
- **Proposed fix:** add `StateStore.get_latest_checkpoint` reuse (it already exists and is unused
  here) and make both handlers use it. Regression test asserting both surfaces agree.

### HIGH-3 — Repository URL "allowlist" allows arbitrary local paths and git option injection
- **File/line:** `app/core/workspace.py:253-266`; consumed at `:112` (`git clone`), and
  `app/api/delegate.py:170`.
- **Root cause:** the final pattern `^[A-Za-z0-9_.\-\/\\]+$` matches any bare filesystem path or
  dash-prefixed token, and `git clone` is invoked with no `--` separator.
- **Evidence:**
  ```
  ALLOWED  '/home/user/Forge'      (arbitrary local repo clone)
  ALLOWED  '/etc'                  (arbitrary local dir)
  ALLOWED  '../../..'              (relative traversal)
  ALLOWED  'file:///etc'
  ALLOWED  '-bare' / '-c'          (leading dash → git option injection)
  $ git clone --depth 1 /tmp/gtest/src dst2   →  "Cloning into 'dst2'... done."
  ```
- **Impact:** an authenticated (or, in dev, unauthenticated) caller can clone any host directory the
  FORGE process can read into a sandbox, and can inject git CLI options. The existing test
  `test_repository_allowlist_validation` only checks `javascript:alert(1)` and an `http://` URL, so
  it gives false confidence.
- **Proposed fix:** tighten to `https?://` + `git@host:owner/repo` + explicit `file://` opt-in,
  reject anything starting with `-`, and pass `--` before the URL. Regression test with the
  payloads above.

### HIGH-4 — Any non-empty `push_token` bypasses the git-push authorization gate
- **File/line:** `app/execution/permissions.py:164-172` (`if not authorized and not push_token`),
  used by `app/execution/git_tool.py:159` and the protected-branch gate at `:170-179`.
- **Root cause:** the gate treats "a token was supplied" as equivalent to "authorization was
  granted". Nothing verifies the token against anything.
- **Evidence:**
  ```
  push_token=None                                  -> BLOCKED
  push_token=''                                    -> BLOCKED
  push_token='x'                                   -> ALLOWED (no exception)
  push_token='totally-bogus-string-from-attacker'  -> ALLOWED (no exception)
  ```
  and the protected-branch check at `git_tool.py:170` uses the same `not push_token` test, so
  `branch='main'` + `push_token='x'` passes both gates.
- **Impact:** the "Git Push Gated Authorization" guarantee in `README.md` and
  `tests/test_prompt4_forge.py::test_git_push_requires_authorization` is defeated by any
  attacker-controlled string. Same shape at `git_tool.py:193` for PR creation (`pr_token`).
- **Proposed fix:** require `authorized=True` **and** a token that matches a server-side configured
  elevated credential (constant-time compare); fail closed otherwise. Regression test asserting
  `push_token='x'` with `authorized=False` raises.

### HIGH-5 — `forge build --push-to-github` / `--github-repo` are silent no-ops
- **File/line:** `app/cli.py:42-43` (params), `:578-579` (passed in), never read in the body.
- **Evidence (AST scan of `handle_build`):**
  ```

### HIGH-6 — `intake_and_plan(context=...)` silently discards the caller's context

### HIGH-7 — `build_task_from_template` writes outside the managed workspace tree and skips sandbox layout
- **File/line:** `app/api/marketplace.py:97` (`workspace_path = settings.workspaces_dir / task_id`)
  and `:105` (`file_path = workspace_path / rel_path`).
- **Root cause:** `settings.workspaces_dir` is the *relative* default `Path("workspaces")`, so the
  target is CWD-relative; `WorkspaceManager.get_task_workspace_dir` resolves against
  `settings.base_dir`. Template `rel_path`s are also written with no containment check.
- **Evidence:**
  ```

  base_dir            : /home/user/Forge
  workspace_manager   : /home/user/Forge/workspaces/task_demo

  `workspace_manager.get_workspace_paths()` resolves `project/` to a non-existent path and
  `GET /api/tasks/{id}/inspect` reports zero files.
- **Proposed fix:** use `workspace_manager` + `write_project_file` (which validates containment), so
  the workspace is created at the canonical path with the standard layout. Regression test asserting
  `get_workspace_paths(task_id).project` exists and contains the rendered files.

### HIGH-8 — `local_path` intake copies arbitrary host directories with no validation
- **File/line:** `app/core/workspace.py:127-141`.
- **Root cause:** `src_path = Path(local_path).resolve()` then `shutil.copytree(...)` — no
  allowlist, no containment, no size cap. Reachable from `POST /api/tasks`, `POST /api/v1/tasks`
  and `POST /api/v1/forge/delegate` (`local_path` / `repository` payload keys).
- **Impact:** resource exhaustion (copying `/` or a huge tree into the sandbox) and host-directory
  disclosure into a workspace whose contents are listed by `/inspect`.
- **Proposed fix:** require the path to exist, be a directory, and be inside an operator-configured
  allowlist of intake roots; bound the copied size. Regression test asserting an out-of-allowlist
  path is rejected.
